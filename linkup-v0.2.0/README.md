# LinkUp 0.2.0 — Android + Linux Mint

Экспериментальная версия, перенос v0.1.0 в устанавливаемые приложения. UI использует локальный встроенный WebView/Qt WebEngine (не PWA, не внешний сайт); агенты Android (Java, Android SDK) и Linux (Python, X11, SQLite) используют системные API и могут собирать активность без открытого окна. Flutter не использован: SDK и сетевой доступ к инструментам отсутствовали в среде разработки. Это компромисс для сохранения работающего кода Transfer и его дизайна.

## Linux Mint

**Вариант A:** `sudo apt install ./LinkUp-v0.2.0-linux.deb` из папки с пакетом. При необходимости включите репозиторий Universe и интернет для установки зависимостей. Запуск LinkUp из меню приложений или командой `linkup`.

**Вариант B:** распаковать исходники и выполнить `bash linux/install.sh`. Установка в `~/.local/opt/linkup`; ярлык в меню и автозапуск агента при входе в сеанс. Для работы активных окон нужен сеанс Cinnamon/X11 (проверка `echo $XDG_SESSION_TYPE`), `xprop`, `xprintidle`. Wayland пока не поддержан. Без X11 нет данных, а не искусственных нулей. Для остановки сбора используйте настройки Activity. Агент по умолчанию не собирает данные. Удаление приложения не удаляет автоматически `~/.local/share/linkup`.

## Android

Для Android 10+ доступен подписанный выпуск v0.2.1. GitHub Actions собирает APK и проверяет его на эмуляторе API 35. Проект использует target/compile SDK 35. Установите Android Studio с SDK Platform 35, Build Tools и JDK 17; откройте папку `android`, дождитесь Gradle Sync, затем Build > Build Bundle(s)/APK(s) > Build APK(s). Альтернатива: Gradle 8.9, ANDROID_HOME/ANDROID_SDK_ROOT и `bash android/build-apk.sh`. Файл `android/app/build/outputs/apk/debug/app-debug.apk`. Установите APK на собственный телефон, разрешив установку из выбранного источника. Приложение не требует root или ADB. Исходники и папка `ui` должны оставаться вместе. Для постоянных обновлений используйте один и тот же ключ подписи, debug-сборки из разных сред могут отличаться.

## Подключение Supabase (на обоих устройствах)

1. Создайте проект Supabase (или используйте v0.1). В SQL Editor выполните [`schema.sql`](schema.sql) из этой папки. Он добавляет `linkup_activity`, таблицу привязки дисков и сохраняет старую `linkup_items`. RLS ограничивает строки владельцем `auth.uid()`. Миграция переносит привязку Google Drive из старой таблицы. Для существующего проекта повторное применение схемы отключает загрузку Activity со старых клиентов и сохраняет уже записанные данные.
2. В Authentication > Users создайте пользователя с email/password. В LinkUp > Настройки укажите HTTPS Project URL, publishable/anon key, email, password и имя устройства. НЕ используйте service_role или secret key.
3. Вход в аккаунт оставляет Transfer локальным. Для обмена на каждом устройстве с тем же аккаунтом отдельно включите «Облачный Transfer» и подтвердите передачу без E2EE. Локальные записи сохраняются на устройстве. Ранее отложенные облачные записи этого аккаунта могут отправиться после согласия.

## Файлы

Яндекс Диск — новый провайдер по умолчанию; Google Drive остаётся альтернативой. Текст передаётся через Supabase без диска. Файлы хранятся отдельно, Supabase содержит ID, имя, размер, источник и время. Один аккаунт Supabase может иметь привязку обоих дисков; для загрузки/скачивания/удаления объектов выберите соответствующий провайдер. Удаление ранее синхронизированной записи скрывает её из облачной истории. Ранее загруженный файл может остаться на диске.

* Яндекс: зарегистрируйте OAuth API application на https://oauth.yandex.ru/client/new/ с правом `cloud_api:disk.app_folder`, получайте access token официальным способом (https://yandex.ru/dev/id/doc/ru/access). На обоих устройствах используйте один и тот же Client ID и аккаунт. Файлы записываются под `app:/<uuid>`. Токен не вводите в чат и не сохраняйте в архив.
* Google: используйте прежний OAuth Client ID и scope `https://www.googleapis.com/auth/drive.appdata`; получите access token через поддерживаемый официальный OAuth flow во внешнем браузере (не встроенный WebView). OAuth Playground с собственными credentials допустим для тестового получения токена при правильном redirect URI; не переносите клиентский секрет в приложение. Google хранит файлы в appDataFolder, загрузка частями 8 МиБ.
* Сначала сохраните настройки Supabase и Client ID и разрешите облачный Transfer, затем снова откройте настройки, вставьте OAuth access token, нажмите «Подключить диск». В этой экспериментальной версии токены дисков только в памяти. После закрытия процесса и при истечении токена нужно повторить подключение. Автоматический нативный OAuth/refresh для диска предстоит реализовать. Кросс-origin запросы к реальному Диску и Supabase из обеих оболочек не проверены.
* Перенесены отправка текста/ссылок/файлов, мультивыбор, история, фильтры, поиск, drag&drop (ПК), копирование, удаление, очистка 1/7/30/90 дней/всей истории и локальная автоочистка. На Android системный выбор файлов, входящие Android Share Intents, сохранение полученных файлов в Downloads/LinkUp. Входящие большие файлы через «Поделиться» и скачивание могут потреблять значительную память; для крупных файлов предпочтителен выбор через системный пикер, лимит зависит от ОС и Диска. Нативный clipboard используется в открытом приложении. Глобальное чтение буфера Android в фоне отсутствует.
* При явном согласии облачный Transfer синхронизируется во время открытого интерфейса (Realtime + резервный опрос 15 секунд); фоновый агент пока занимается только Activity. Если UI закрыт, очередь Transfer будет отправлена при следующем запуске. Файлы, уже загруженные в облако, доступны при выключенном другом устройстве.

## Activity

Откройте «Активность» → иконка настроек. Сбор выключен по умолчанию. Включайте только для своих устройств. Android: включите «Приложения» и разрешите доступ к статистике использования для LinkUp. Геолокацию можно отдельно включить при работающем сборе и выданном разрешении. Для фоновых точек разрешите «Всегда» в системных настройках приложения, если прошивка это позволяет. Периодическое задание JobScheduler примерно раз в 15 минут (ОС может отложить), дополнительно сбор при возвращении в приложение. Android использует события ACTIVITY_RESUMED/PAUSED, SCREEN_INTERACTIVE, KEYGUARD_HIDDEN и др.; не читает содержимое приложений. История событий в ОС ограничена несколькими днями, начиная с разрешения данные записываются в локальную SQLite. Разделённый экран, переходы внутри приложения, выключение/перезагрузка и отсутствие системных событий могут снижать точность. GPS/сетевые координаты только если Android предоставит свежую точку; нет непрерывной записи, точного маршрута или гарантии периодичности. Локации отображаются координатами, временем, источником, точностью и ссылкой на карту. При открытии карты координаты передаются OpenStreetMap по вашему действию.

Linux: активное X11-окно по WM_CLASS, опрос ~5 с, текущая сессия сохраняется фрагментами примерно каждые 15 с, паузы/сон не экстраполируются, idle >=60 с исключается. Блокировки распознаются через доступный D-Bus screensaver API; не все окружения поддерживаются. Linux не собирает координаты. Список сайтов внутри браузера, нажатия клавиш, текст окон и приватные данные приложений не собираются. Сбор начинается после включения.

Activity хранится в локальной SQLite и работает при выключенной сети. В таймлайне можно выбрать дату и открыть цветную отметку с названием приложения и диапазоном времени. Иконка диагностики показывает состояние источника и копирует сводку без имён приложений и точных времён использования.

Облачная Activity приостановлена до E2EE. Старые облачные записи остаются в Supabase. Схема оставляет владельцу доступ к ним и возможность удаления. Примените обновлённую схему в отдельном тестовом проекте перед изменением действующего проекта. Для остановки сбора или удаления локальной истории используйте панель источников.
