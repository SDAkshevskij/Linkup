# LinkUp 0.2.0 — Android + Linux Mint

Экспериментальная версия, перенос v0.1.0 в устанавливаемые приложения. UI использует локальный встроенный WebView/Qt WebEngine (не PWA, не внешний сайт); агенты Android (Java, Android SDK) и Linux (Python, X11, SQLite) используют системные API и могут собирать активность без открытого окна. Flutter не использован: SDK и сетевой доступ к инструментам отсутствовали в среде разработки. Это компромисс для сохранения работающего кода Transfer и его дизайна.

## Linux Mint

**Вариант A:** `sudo apt install ./LinkUp-v0.2.0-linux.deb` из папки с пакетом. При необходимости включите репозиторий Universe и интернет для установки зависимостей. Запуск LinkUp из меню приложений или командой `linkup`.

**Вариант B:** распаковать исходники и выполнить `bash linux/install.sh`. Установка в `~/.local/opt/linkup`; ярлык в меню и автозапуск агента при входе в сеанс. Для работы активных окон нужен сеанс Cinnamon/X11 (проверка `echo $XDG_SESSION_TYPE`), `xprop`, `xprintidle`. Wayland пока не поддержан. Без X11 нет данных, а не искусственных нулей. Для остановки сбора используйте настройки Activity. Агент по умолчанию не собирает данные. Удаление приложения не удаляет автоматически `~/.local/share/linkup`.

## Android

В текущей среде не было Android SDK/Gradle, поэтому APK не собран и компиляция Java с Android API не проверена. Проект предназначен для Android 10+; target/compile SDK 35. Установите Android Studio с SDK Platform 35, Build Tools и JDK 17; откройте папку `android`, дождитесь Gradle Sync, затем Build > Build Bundle(s)/APK(s) > Build APK(s). Альтернатива: Gradle 8.9, ANDROID_HOME/ANDROID_SDK_ROOT и `bash android/build-apk.sh`. Файл `android/app/build/outputs/apk/debug/app-debug.apk`. Установите APK на собственный телефон, разрешив установку из выбранного источника. Приложение не требует root или ADB. Исходники и папка `ui` должны оставаться вместе. Для постоянных обновлений используйте один и тот же ключ подписи, debug-сборки из разных сред могут отличаться.

## Подключение Supabase (на обоих устройствах)

1. Создайте проект Supabase (или используйте v0.1). В SQL Editor выполните **корневой `schema.sql`**. Он добавляет `linkup_activity`, таблицу привязки дисков и сохраняет старую `linkup_items`. RLS ограничивает строки владельцем `auth.uid()`. Миграция переносит привязку Google Drive из старой таблицы. SQL не исполнялся на живом проекте в среде разработки.
2. В Authentication > Users создайте пользователя с email/password. В LinkUp > Настройки укажите HTTPS Project URL, publishable/anon key, email, password и имя устройства. НЕ используйте service_role или secret key.
3. Войдите в один аккаунт на телефоне и ПК. Локальная история и облачная история разделены, локальные записи старого PWA автоматически не импортируются. Существующие облачные записи доступны через тот же аккаунт и соответствующий диск.

## Файлы

Яндекс Диск — новый провайдер по умолчанию; Google Drive остаётся альтернативой. Текст передаётся через Supabase без диска. Файлы хранятся отдельно, Supabase содержит ID, имя, размер, источник и время. Один аккаунт Supabase может иметь привязку обоих дисков; для загрузки/скачивания/удаления объектов выберите соответствующий провайдер. Удаление облачного объекта выполняется при наличии подключения и нужного токена.

* Яндекс: зарегистрируйте OAuth API application на https://oauth.yandex.ru/client/new/ с правом `cloud_api:disk.app_folder`, получайте access token официальным способом (https://yandex.ru/dev/id/doc/ru/access). На обоих устройствах используйте один и тот же Client ID и аккаунт. Файлы записываются под `app:/<uuid>`. Токен не вводите в чат и не сохраняйте в архив.
* Google: используйте прежний OAuth Client ID и scope `https://www.googleapis.com/auth/drive.appdata`; получите access token через поддерживаемый официальный OAuth flow во внешнем браузере (не встроенный WebView). OAuth Playground с собственными credentials допустим для тестового получения токена при правильном redirect URI; не переносите клиентский секрет в приложение. Google хранит файлы в appDataFolder, загрузка частями 8 МиБ.
* Сначала сохраните настройки Supabase и Client ID, затем снова откройте настройки, вставьте OAuth access token, нажмите «Подключить диск». В этой экспериментальной версии токены дисков только в памяти. После закрытия процесса и при истечении токена нужно повторить подключение. Автоматический нативный OAuth/refresh для диска предстоит реализовать. Кросс-origin запросы к реальному Диску и Supabase из обеих оболочек не проверены.
* Перенесены отправка текста/ссылок/файлов, мультивыбор, история, фильтры, поиск, drag&drop (ПК), копирование, удаление, очистка 1/7/30/90 дней/всей истории и локальная автоочистка. На Android системный выбор файлов, входящие Android Share Intents, сохранение полученных файлов в Downloads/LinkUp. Входящие большие файлы через «Поделиться» и скачивание могут потреблять значительную память; для крупных файлов предпочтителен выбор через системный пикер, лимит зависит от ОС и Диска. Нативный clipboard используется в открытом приложении. Глобальное чтение буфера Android в фоне отсутствует.
* Transfer синхронизируется во время открытого интерфейса (Realtime + резервный опрос 15 секунд); фоновый агент пока занимается только Activity. Если UI закрыт, очередь Transfer будет отправлена при следующем запуске. Файлы, уже загруженные в облако, доступны при выключенном другом устройстве.

## Activity

Откройте «Активность» → иконка настроек. Сбор выключен по умолчанию. Включайте только для своих устройств. Android: «Системный доступ» → разрешить доступ к статистике использования для LinkUp. Геолокация включается отдельным переключателем и отдельным разрешением. Для фоновых точек разрешите «Всегда» в системных настройках приложения, если прошивка это позволяет. Периодическое задание JobScheduler примерно раз в 15 минут (ОС может отложить), дополнительно сбор при возвращении в приложение. Android использует события ACTIVITY_RESUMED/PAUSED, SCREEN_INTERACTIVE, KEYGUARD_HIDDEN и др.; не читает содержимое приложений. История событий в ОС ограничена несколькими днями, начиная с разрешения данные записываются в локальную SQLite. Разделённый экран, переходы внутри приложения, выключение/перезагрузка и отсутствие системных событий могут снижать точность. GPS/сетевые координаты только если Android предоставит свежую точку; нет непрерывной записи, точного маршрута или гарантии периодичности. Локации отображаются координатами, временем, источником, точностью и ссылкой на карту. При открытии карты координаты передаются OpenStreetMap по вашему действию.

Linux: активное X11-окно по WM_CLASS, опрос ~5 с, сессии режутся на фрагменты ~1 мин, паузы/сон не экстраполируются, idle >=60 с исключается. Блокировки распознаются через доступный D-Bus screensaver API; не все окружения поддерживаются. Linux не собирает координаты, но показывает данные Android из облака. Список сайтов внутри браузера, нажатия клавиш, текст окон и приватные данные приложений не собираются. Сбор начинается после включения.

Облако Activity — независимая авторизация, чтобы обновления продолжались при закрытом UI. Включите «Синхронизировать активность с Supabase» и один раз введите пароль текущего аккаунта. Пароль не сохраняется; сессия хранится в приватном хранилище приложения. Новые записи после включения облака принадлежат текущему аккаунту. Старые локальные записи не выгружаются автоматически. Android отправляет пакетами до 200 событий по расписанию/при открытии; Linux проверяет очередь примерно каждые 30 с. Повторный upload идемпотентен. При наличии аккаунта UI объединяет локальные и облачные события, исключая дубли по UUID. Суммарное активное время — объединение интервалов всех устройств, не сумма пересекающихся интервалов. По приложениям время суммируется по устройствам; разблокировки — события, где ОС их предоставила. Интервалы обрезаются по выбранной локальной дате; сутки перехода летнего времени — особый случай, метки часов визуально приблизительны. Нажатие на цветной участок показывает приложение и диапазон времени.

В настройках можно выключить сбор, геолокацию, облако и удалить локальную историю (облачная копия остаётся). Для окончательной очистки облака сначала выключите облачную синхронизацию на **всех** устройствах и удалите локальные данные, затем удалите строки своей учётной записи в `linkup_activity` через Supabase Dashboard / SQL Editor. Локальные данные, Supabase refresh-токены и метаданные пока не защищены E2EE; Android хранит их в приватной области приложения, Linux — в каталоге пользователя с правами 0700. Не подключайте посторонние устройства. Сбор координат чувствителен: включайте облачную историю только если это действительно нужно.

## Проверки

`node --test tests/*.mjs` — 7 тестов: transport mocks, Realtime, Google Drive, Яндекс Диск, объединение времени, цвета. `python3 tests/test_agent.py` — 4 теста SQLite/состояния/сбора. `python3 -m py_compile linux/*.py`, `bash -n linux/install.sh android/build-apk.sh`, `node --check` для JS. На момент выпуска нет Android SDK, Qt WebEngine, реальных облачных credentials; браузерная среда ограничена Chromium URLBlocklist. APK не собран, .deb сформирован из исходников, установка на реальном Linux Mint не проверена. Не production-релиз.

Для удалённой сборки Android без локального SDK в архив включён `.github/workflows/android.yml`: загрузите **содержимое** `linkup-v0.2.0` в корень личного GitHub-репозитория, включите Actions, запустите `Android debug APK` вручную и скачайте артефакт `LinkUp-Android-debug`, если сборка успешно завершится. Workflow не был запущен или проверен в GitHub; debug-подпись от разных CI-сборок может различаться, поэтому для обновлений без переустановки нужна постоянная подпись.
