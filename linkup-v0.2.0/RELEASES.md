# Выпуски и обновления LinkUp

## Android

Скачайте APK своего релиза и установите его поверх предыдущего. Идентификатор пакета `io.linkup.app`, источник WebView и каталоги данных остаются прежними. Android требует большей версии и той же подписи, чтобы установить APK поверх старого приложения. При таком обновлении сохраняются настройки, сессии, история Transfer и Activity. Токены облачного диска, которые приложение держит только в памяти, нужно вводить заново после перезапуска.

В LinkUp откройте **Настройки → Проверить обновления**. Приложение покажет описание релиза, скачает APK после подтверждения и проверит контрольную сумму, идентификатор пакета, версию и сертификат. Подтвердите установку в Android. Если Android запросит разрешение на установку из LinkUp, его можно дать в системных настройках и повторно подтвердить установку.

### Переход с раннего debug APK

Ранние CI APK подписывались одноразовым ключом. Если сертификат установленного APK отличается от сертификата релиза, Android отклонит установку поверх него. Оставьте debug APK установленным, пока не сохраните важные данные и не проверите копии.

1. Скопируйте важный локальный текст и ссылки и скачайте локальные вложения из Transfer. Проверьте с другого устройства, какие записи и файлы действительно доступны в облаке.
2. Для Activity проверьте принятые сервером записи. Локальная история Activity не имеет импорта или экспорта через интерфейс этой версии. Если нужно сохранить её целиком, оставьте debug APK на старом устройстве или дождитесь миграции для этого вида данных.
3. Удаление Android-приложения стирает локальную историю, настройки и сессии. Проводите чистую установку релиза только после проверки копий. Затем подключите облако и загрузите ранее сохранённые локальные файлы при необходимости.

## Linux Mint

Для установки распакуйте проверенный ZIP и из каталога архива запустите:

```sh
bash linux/install.sh
```

При первой установке скрипт предложит системную установку зависимостей, если PyQt5, Qt WebEngine, Qt WebChannel или утилиты X11 отсутствуют. Для существующей установки 0.2.0 достаточно один раз закрыть её окно и запустить скрипт нового релиза. Старый агент завершится при выходе из сеанса. После повторного входа его запускает новый путь автозапуска.

Затем используйте **Настройки → Проверить обновления**. Программа сверяет хеш ZIP с метаданными GitHub, распаковывает пакет во временный каталог, переключает версию после подтверждения и перезапускает интерфейс. Агент сам переключится на новую версию. Если окно новой версии не загрузится, указатель на предыдущую версию будет восстановлен. Повышение прав для встроенного обновления не требуется. SQLite и профиль Qt WebEngine остаются в `${XDG_DATA_HOME:-$HOME/.local/share}/linkup`.

## Подготовка постоянного ключа и выпуск

Владелец создаёт PKCS12 с alias `linkup` локально и хранит зашифрованную резервную копию ключа и пароль отдельно. Например:

```sh
keytool -genkeypair -storetype PKCS12 -keystore /private/path/linkup-release.p12 \
  -alias linkup -keyalg RSA -keysize 3072 -validity 10000 -dname 'CN=LinkUp'
```

После ревью workflow настройте GitHub Environment `linkup-release` для деплоев только из `main`. Укажите подтверждающего ревьюера, если репозиторий использует ручное подтверждение деплоя. Создайте в этом окружении `LINKUP_KEYSTORE_BASE64` из PKCS12 и `LINKUP_KEYSTORE_PASSWORD`. Передавайте значения через настройки секретов или локальный CLI. Не сохраняйте ключ, пароль или закодированный PKCS12 в Git, артефактах и обратной связи.

Для последующих выпусков увеличивайте `versionCode` и `versionName` в `version.properties`. Выполните ручной запуск **LinkUp release** из проверенного `main`. Workflow запускает проверки Android/Linux, собирает неподписанный release APK и подписывает его в отдельном job из защищённого окружения. Он сверяет сертификат с ключом и предыдущим опубликованным APK, проверяет, что `versionCode` вырос и публикует с тегом `v<versionName>` файлы `LinkUp-Android-<versionCode>.apk`, `LinkUp-Linux-<versionCode>.zip` и `SHA256SUMS`. Скачанные файлы можно проверить командой `sha256sum -c SHA256SUMS`. Если публикация остановилась на черновике, проверьте загруженные файлы перед повтором или удалением черновика.

## Подключение к облаку

Введите HTTPS Project URL, publishable/anon key, email и пароль. Нажмите **Сохранить и подключить** в разделе Supabase. LinkUp показывает ход входа и проверки таблицы Transfer. При ошибке 404 проверьте URL и применённую схему. При 401/403 проверьте ключ, данные входа и права. После подключения Supabase сохраните провайдера и OAuth Client ID, введите токен и нажмите **Подключить диск**. Состояния проверки токена и привязки отображаются в разделе диска.
