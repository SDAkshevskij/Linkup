# Open Source First — LinkUp
Research snapshot: 2026-11-28. This is a mandatory planning process and a preliminary candidate register, not a dependency approval or implementation report.

## Binding rules for planners and implementers
- Before defining a substantial task, the planner (including ChatGPT) independently searches existing open-source implementations, official SDKs and relevant tests for EVERY material subtask. Add the findings to the task plan, linking concrete upstream repositories and files where known. Do not delegate all research to the executor.
- Before coding, the executor repeats/updates the search and inspects the actual source, dependency graph, tests, license files and maintenance history. For each task, compare the cost/risk of adopting a library, adapting code, using a reference, and keeping/writing a small native solution. Prefer reuse when it demonstrably reduces complexity or risk; do not adopt dependencies just to meet a quota.
- Record a decision per substantial subtask (adopt / adapt / reference / retain or build) with upstream URL, exact tag/commit, paths/API, license/SPDX and notices, dependency/model/dictionary licenses, platform compatibility, tested evidence, rationale, risks, and maintenance strategy. If source access is blocked or there is no suitable candidate, say so and record searches; do not pretend reuse.
- Publicly visible source without a license is not automatically reusable. GPL/MPL and other copyleft requirements must be assessed for the actual combined distribution; retain copyright/NOTICE, publish corresponding source and modifications as required. Separate APKs alone do not prove licensing independence. Do not change project licensing without owner approval. If unclear, use as a reference only and do not copy code.
- Pin chosen revisions and package versions; review vulnerabilities, transitive licenses, network/telemetry, permissions, update cadence, build reproducibility and cost. Keep a third-party inventory with upstream revision and modifications, and attribution in distributed artifacts. Never execute arbitrary upstream setup scripts blindly.
- Do not silently introduce a cloud service, paid API, new privileged permission, telemetry, mandatory Shizuku/root, data collection, alternate protocol, or architecture migration. Preserve Android/Linux native functionality, offline delivery, local storage and the owner-approved security gates. Ask for approval when a choice materially changes those contracts.
- Reuse upstream regression tests/fixtures where licensed, adapt them to LinkUp, and independently test the real integration on our platforms. Upstream green CI is not evidence that LinkUp works.
- Reuse mechanics, not generic visual output. Preserve the distinctive LinkUp UX and the full PRODUCT_QUALITY.md bar. An open-source widget is acceptable only if the resulting interaction and appearance are deliberately designed.
- Add a short reuse decision table to every substantial implementation plan/PR. Maintain this candidate register as research evolves. No new candidate is implicitly accepted by its inclusion here.

## Upstream license screening (not full audit)
- HeliBoard and ClipCascade explicitly identify GPLv3; KDE Connect Android reports GPL-2.0. Check individual files and exact SPDX variants before use.
- libsodium ISC; whisper.cpp MIT; whisperIME MIT. Verify the pinned revision and any additional linked code, weights or model files.
- LinuxDrop and LocalSend have Apache license files; vis-timeline ships MIT and Apache license texts. Confirm applicable terms and NOTICE files at the revision.
- ActivityWatch components may have different licenses; inspect each component independently (aw-android, window, AFK, Wayland, web UI). Do not apply a parent repository license to the whole ecosystem.
- For all other candidates, license verification remains open. This register does not grant permission to copy.
